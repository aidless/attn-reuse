# 索引重叠能预测复用的代价吗——GPT-2 上的直接测量

日期：2026-11-14
脚本：`scanner/reuse_effect.py`；数据 `data/reuse_gpt2_g{2,3,4,6,12}.json`、`data/reuse_single.json`
前置：`reports/01-cross-layer-premise.md`（重叠的四条对照）、`reports/02-k-sweep.md`（k 稳健性）

## 1. 问题

`01` 与 `02` 只回答了一半：跨层复用的**动机论据**（相邻层选同样的 token，因此可以复用）缺少对照，量级被同层现象吃掉。但这不构成反对复用的理由——重叠高不等于代价高，也可能重叠高且几乎无损。

要把这条线接上，必须直接测代价。本报告测两件事：

1. 复用多少层，代价多大（剂量—反应曲线）；
2. **索引重叠能否预测单层复用的代价**（这是整条论证链最关键的一环）。

## 2. 实验设置

DeepSeek-V4.1 的 CSA2 是每 6 层一组、组首 Full、其余 5 层 Reuse（`deepseek-research/evidence/v41_architecture_facts.md`）。在没有真实稀疏 indexer 的情况下，dense 模型上能做的最接近的代理是：**把组内后续层的 attention 输出直接替换为组首层的输出**。这就是「复用」在计算图上的含义，只不过被复用的是 dense 全量输出，而不是一组 top-k 索引的加权和。

模型 GPT-2（12 层，124M），CPU，2 条 60–80 token 的英文文本，teacher-forcing 损失。`--selftest` 三项：hook 确实改变输出、`group=1` 逐位复现 baseline、交叉熵计算与直接计算一致。

**这个代理偏保守**：dense 全量输出携带的信息多于 top-k 加权和，所以真实系统复用索引的代价预计不会比这里更大。反向不成立——下面的绝对数字不能外推到 552B 模型。

## 3. 剂量—反应：复用越多，代价越大且非线性

| 组大小 | 复用层数 | 平均 Δloss | 文本 1 的 ppl（base 43.7） |
|---|---|---|---|
| 12（全复用） | 11 | +3.1145 | 958.7 |
| 6 | 10 | +2.5833 | 555.7 |
| 4 | 9 | +2.2016 | 378.4 |
| 3 | 8 | +1.7880 | 250.9 |
| 2 | 6 | +0.9326 | 98.8 |

单调，且明显非线性：从「复用 6 层」到「复用 11 层」，复用层数增加不到一倍，损失增加 3.3 倍。

**但单层复用几乎无损**：

| 层对 | 重叠 | Δloss |
|---|---|---|
| 0→1 | 0.2846 | +0.5738 |
| 1→2 | 0.3667 | +0.0412 |
| 2→3 | 0.5577 | +0.0655 |
| 3→4 | 0.4825 | +0.0398 |
| 4→5 | 0.3596 | +0.0612 |
| 5→6 | 0.3488 | +0.0406 |
| 6→7 | 0.3692 | +0.0837 |
| 7→8 | 0.3672 | +0.0444 |
| 8→9 | 0.3286 | +0.0317 |
| 9→10 | 0.3093 | +0.0517 |
| 10→11 | 0.2936 | +0.0880 |

除第 0→1 对外，单层复用把损失推高 0.03–0.09，ppl 恶化约 3–9%。**代价随复用层数累积得很快**：单层 5% 的代价，6 层就是 2.3 倍 ppl。（来源: attn-reuse/data/reuse_single.json 与 attn-reuse/data/reuse_groups.json）

## 4. 关键读数：重叠不预测代价

把上表两列对齐做相关：

- 全部 11 对：Pearson r = **−0.349**，Spearman = −0.264
- 排除明显异常的第 0→1 对（第 0 层输出服务于整个残差流的初始状态，不能当普通层）：**Pearson r = −0.055（n=10）**

即：**在 0.29 到 0.56 的重叠区间里，重叠高低与复用代价基本无关。**

这直接打断了两篇论文的论证链。它们的推理是「重叠高 → 冗余大 → 可复用」。实测是：两个层可以选中同一批 token，但给它们不同的权重、各自的 value 与输出投影也不同，所以输出的可替换性并不由选中的位置集合决定。

**索引重叠是必要条件，不是充分条件，而且在这里连预测能力都没有。**

## 5. 这条结论的边界

能说的：
- 在 GPT-2 上，组内跨层复用 attention 输出的代价随复用层数非线性增长；
- 单层复用的代价与相邻层索引重叠不相关；
- 因此「索引重叠」不能作为复用决策的依据。

不能说的：
- 这些绝对数字适用于稀疏 indexer 或大模型。这里是 dense 全量输出复用，是代价的上界形态。
- GPT-2 的 12 层结构与 40 层、6 层一组的 CSA2 结构不可类比。真正的检验需要在有 indexer 的实现上做。
- 2 条文本、teacher forcing、无下游任务评估。这里的损失是语言建模损失，不是任务性能。

## 6. 下一步（这条线要成为研究还缺什么）

1. 在 `fla-org/native-sparse-attention` 或 `MoonshotAI/MoBA` 上做同样的替换实验——它们的复用对象是索引，与本报告不同。这需要 GPU 和一次真实训练/推理，本机 `cuda.is_available()=False`。
2. 把「重叠—代价」的散点扩到 40 层 × 多个模型，检验 r ≈ 0 是否是普遍现象而非 GPT-2 的偶然。
3. 找到能预测代价的量。已知重叠不行；候选是「层间 value 投影的余弦相似度」或「输出表示的 CKA」。**这才是可能形成方法贡献的方向**——如果存在一个廉价代理量能预测复用代价，复用决策就有了依据。

## 7. 复现

```bash
cd attn-reuse
HF_HUB_OFFLINE=1 python3 scanner/reuse_effect.py --selftest   # 权重已缓存时离线跑，避免 hf-mirror 超时
python3 scanner/reuse_effect.py --model openai-community/gpt2 --group 6 --json data/reuse_gpt2_g6.json
python3 scanner/reuse_effect.py --model openai-community/gpt2 --all-single --json data/reuse_single.json
```

CPU 墙钟：`--group` 每次约 40 秒，`--all-single` 约 4 分钟（22 次前向）。
